# 寵物買賣紀錄及晶片使用情形表 — 自動產出功能規格

> 給 lovecat.cc CMS（小小貓屋 / 橘映之境工作坊）實作用的完整規格書。
> 目標：在後台一鍵產出符合動保處格式的「寵物買賣紀錄及晶片使用情形表」Word 檔，
> 可指定日期區間，並支援「只出在養」與「補新來的貓」兩種模式。
>
> 本規格由實際人工整理 151 隻貓的完整流程反推而成，所有規則都經過與農業部四份官方匯出逐筆對帳驗證。

---

## 0. 為什麼需要這份規格

特定寵物業依法須保存「寵物買賣紀錄及晶片使用情形表」備查。
目前是人工把**農業部匯出的資料**＋**官方登記證明 PDF** 逐筆謄到 Word 表格，
每新增一隻貓或賣出一隻就要重編、重排序，極易漏填或填錯欄位。

本功能把整個流程自動化：**資料進來 → 依規則轉換 → 產出 Word**。

## 1. 名詞定義（非常重要，先讀這段）

這些定義是整套邏輯的基礎，實作時務必照這個語意，不要自行推論。

| 名詞 | 定義 | 備註 |
| --- | --- | --- |
| **轉入** | 貓**進到**本店（橘映之境工作坊）名下 | ＝**購入** |
| **轉出** | 貓**離開**本店名下 | ＝**售出** |
| **在養** | 目前仍登記在本店名下 | 對應官方「登記寵物名單（是否除戶＝否）」 |
| **除戶** | 官方名冊已除戶 | 對應官方「登記寵物名單（是否除戶＝是）」 |
| **他場** | 這隻貓是從哪個場來的 | 判定規則見 §5.2，**不是**單純抓來源母貓的飼主 |
| **本店** | 橘映之境工作坊，特寵業字第 **S1150011** 號 | 小小貓屋為對外品牌名 |

> ⚠️ **最容易搞錯的一點**：官方登記證明 PDF 上印的是「**這隻晶片目前的登記飼主**」，
> 不是「本店賣給誰」。貓被客人再轉手後，PDF 上會變成第三手的人。
> **買方一律以「轉讓歷程」的「新飼主」為準**，不可用 PDF 的現任飼主。詳見 §5.3。

## 2. 資料來源

全部來自農業部寵物登記管理資訊網（pet.gov.tw），以業者帳號登入後匯出。

| # | 來源 | 格式 | 內容 | 用途 |
| --- | --- | --- | --- | --- |
| A | **寵物轉讓歷程** | .xlsx | 轉讓類型／辦理日期／寵物晶片／新原飼主／飼主姓名／辦理機關／登記證 | **主資料表**：決定狀態、售出日期、買方、他場 |
| B | **登記寵物名單（在養）** | .xlsx | 編號／登記轉讓日期／晶片／寵物名稱／性別／品種／是否除戶／來源母貓晶片／來源母貓原登記飼主 | 校驗在養名單、補品種 |
| C | **登記寵物名單（除戶）** | .xlsx | 同上，是否除戶＝是 | 判定除戶 |
| D | **官方登記證明 PDF** | .pdf ×N | 一隻一份，檔名 `{15碼晶片}_生日{YYYYMMDD}.pdf` | **出生日期唯一可信來源**；另可取母晶片、買方聯絡資料 |

### 2.1 資料來源 A 的欄位結構

```
轉讓類型 | 辦理日期   | 寵物晶片        | 新/原飼主              | 飼主姓名   | 辦理機關       | 登記證
轉出    | 2026/09/10 | 900073001083522 | L222961693            | 林佳怡    | 橘映之境工作坊 | T20260910172414650
轉入    | 2026/07/12 | 900073001084998 | 特寵業繁字第S1110039號 | 街角貓舍   | 街角貓舍      | T20260712202627433
```

- `新/原飼主`：個人＝身分證/居留證/護照號碼；業者＝特寵業字號
- `登記證`：`T` 開頭 17 碼，**前綴後的數字即時間戳**，可直接字串排序＝時間排序（重要，見 §5.1）

### 2.2 官方 PDF 檔名規則

```
{15碼晶片號碼}_生日{YYYYMMDD}.pdf     例：900073001084455_生日20260512.pdf
{15碼晶片號碼}_官方登記.pdf            （官方查無生日時）
```

- 生日只取官方 `PETYEAR` 欄位，**不是**登記日 `IDATE`、**不是**轉讓日 `TDATE`
- **晶片號碼是唯一關聯鍵**，不可用貓名／品種／毛色比對（會重複）

## 4. 功能需求

### 4.1 主功能：一鍵產出

**入口**：後台 → 💳 晶片 → 📄 產生晶片使用情形表

**操作流程**：
1. 選擇產出模式（見 4.2）
2. 選擇日期區間（見 4.3）
3. 按「產生」→ 下載 .docx

### 4.2 產出模式

| 模式 | 內容 | 用途 |
| --- | --- | --- |
| **全部** | 已售出 ＋ 除戶 ＋ 在養 | 完整備查表（預設） |
| **只出在養** | 僅在養列 | 快速盤點現有庫存 |
| **補新來的貓** | 僅「區間內新轉入且尚未出現在既有表」的貓 | 增量補登，不重出舊資料 |

### 4.3 日期區間選擇

UI：兩個日期選擇器 `起日` ~ `迄日`（年/月/日），預設本年度 1/1 ~ 今天。

**篩選邏輯：各分類用各自的關鍵日期**

| 分類 | 篩選依據 |
| --- | --- |
| 已售出 | **售出日期**（＝最後一筆轉出的辦理日期） |
| 除戶 | **除戶日期** |
| 在養 | **轉入日期**（＝最後一筆轉入的辦理日期） |

> 例：選 2026/04/01 ~ 2026/06/30，
> 會出現「該區間售出的貓」＋「該區間除戶的貓」＋「該區間轉入且目前仍在養的貓」。

## 5. 核心業務規則（實作重點）

### 5.1 狀態判定

對每一隻晶片，取出它在**轉讓歷程**中的所有紀錄，依 `登記證` 字串**由小到大**排序（＝時間序），取**最後一筆**：

```
最後一筆 = 轉出  →  已售出
最後一筆 = 轉入  →  在養
```

再用**除戶名單**覆蓋：**只要出現在除戶名單，一律判為除戶**（優先級最高）。

```
優先級：除戶名單 > 轉讓歷程最後一筆
```

> ⚠️ 除戶不會出現在轉讓歷程裡（除戶不是轉讓），所以一定要另外比對除戶名單。
> 實例：`90007-30010-84450`、`90007-30010-84457` 歷程上只有轉入沒有轉出，
> 但官方除戶名單有它們 → 必須判為除戶。

### 5.2 他場名稱與繁字號判定

```
他場名稱 = 最近辦理變更登記站
    例外：若「最近辦理變更登記站」＝ 橘映之境工作坊（本店自己），
          則改用「來源母犬貓原登記飼主」
```

**為什麼有例外**：當轉入的辦理機關是本店自己時，「最近變更登記站」會顯示本店，
寫成他場＝自己沒有意義，此時要往前追來源。

**繁字號**：依他場名稱查對照表（§8），查無則留空並回報給使用者補。

### 5.3 買方判定（最容易出錯）

```
買方 = 轉讓歷程中「最後一筆轉出」的  飼主姓名 + 新/原飼主(證號)
```

**絕對不可**用官方 PDF 上的「現任飼主」。

**原因實例**：`99000-20001-78681` 本店於 2026/05/13 轉出給「派特飛貓舍」，
但該貓後續又被派特飛轉手，官方 PDF 現在印的是第三手的人。
本店的買賣紀錄要記的是**本店賣給誰**＝派特飛貓舍。

**買方聯絡資料**：
- 個人買方：從該筆轉讓的官方登記證明 PDF 取電話／戶籍地址
- 業者買方：查業者對照表（§8）取證號與地址

### 5.4 退回再售（round-trip）

同一隻貓可能出現「轉出 → 轉入 → 轉出」。
**一律以最後一筆轉出為準**（最新的買方）。

實例：`90007-30010-84453` 於 08/02 售予林雨涵，退回後 08/05 再售詹家銓 → 記詹家銓。

### 5.5 出生日期

**唯一來源＝官方登記證明 PDF 的檔名**（`_生日YYYYMMDD`）。
⛔ 不可用登記日期、轉讓日期頂替，⛔ 不可推算。查不到就留空。

### 5.6 毛色

官方轉讓證明**沒有毛色欄位**。處理方式：

1. 若本店 CMS 有該貓的實際毛色 → **優先使用實際值**
2. 若無 → 依**該品種在現有表內的毛色分佈**做加權隨機抽取

```python
# 依品種比例隨機（固定亂數種子以確保可重現）
random.seed(FIXED_SEED)
pool = defaultdict(list)
for row in existing_rows:
    if row.breed and row.color:
        pool[row.breed].append(row.color)   # 出現幾次就放幾次 = 加權
color = random.choice(pool[breed])
```

**實際分佈參考**（151 隻樣本）：

| 品種 | 毛色分佈 |
| --- | --- |
| 英國短毛貓 | 藍 28／藍白 11／銀白 5／奶油 2／虎斑 1 |
| 美國短毛貓 | 銀白 15／奶油 1／橘 1 |
| 布偶貓 | 山貓重點 7／奶油 3／白 2 |
| 曼赤肯貓 | 三花 5／銀白 3／橘色 2／藍三花 1／賓士 1／奶油 1 |
| 小步舞曲(拿破崙短腿貓) | 白 2／藍白 2／山貓重點 1／三花 1 |
| 英國長毛貓 | 奶油 1／橘加白 1／銀白 1 |

> ⚠️ UI 必須標示「毛色為系統依品種比例推估，非實際毛色」，並提供手動修改。

### 5.7 品種正規化

匯出資料會有簡寫與全形空白，需正規化後再比對：

```
美短   → 美國短毛貓
英短   → 英國短毛貓
小步舞曲 → 小步舞曲(拿破崙短腿貓)
（並 strip 尾端全形空白）
```

### 5.8 排序規則

產出時依下列順序排列：

```
1. 已售出  — 依 售出日期 遞增
2. 除戶    — 依 除戶日期 遞增
3. 在養    — 依 轉入日期 遞增
（同日期則以晶片號碼排序，確保結果穩定）
```

type ChipStatus = 'SOLD' | 'IN_STOCK' | 'DEREGISTERED';

interface ChipRecord {

  buyerPhone: string | null;
  buyerAddress: string | null;

interface TransferLog {           // 轉讓歷程原始紀錄

  date: string;
  chipNumber: string;
  counterpartyIdNo: string;
  counterpartyName: string;
  handlingAgency: string;          // 辦理機關 → 用於他場判定

## 9. 對帳與驗證（必做）

每次產出前自動執行，有異常要擋下並提示：

### 9.1 四方對帳

| 檢查 | 條件 |
| --- | --- |
| 總數 | 表內總筆數 ＝ 轉讓歷程去重後的晶片數 |
| 在養 | 表內在養集合 **逐筆等於** 官方在養名單 |
| 除戶 | 表內除戶集合 **逐筆等於** 官方除戶名單 |
| 出生日期 | 每筆與官方 PDF 檔名的生日一致 |

> ⚠️ 只比對「總數」不夠，**必須逐筆比對晶片號碼集合**。

## 附錄 A：狀態判定虛擬碼

```python
def resolve_status(chip, transfer_logs, deregistered_set):
    if chip in deregistered_set:
        return 'DEREGISTERED'
    logs = [l for l in transfer_logs if l.chip == chip]
    if not logs:
        return None                      # 不屬於本店經手
    latest = max(logs, key=lambda l: l.cert_serial)   # 字串排序 = 時間排序
    return 'SOLD' if latest.type == '轉出' else 'IN_STOCK'


def resolve_source_facility(chip, transfer_logs, stock_row):
    ins = [l for l in transfer_logs if l.chip == chip and l.type == '轉入']
    if not ins:
        return None
    latest_in = max(ins, key=lambda l: l.cert_serial)
    facility = latest_in.handling_agency          # 最近辦理變更登記站
    if facility == OUR_SHOP_NAME:                 # 例外：是本店自己
        facility = stock_row.mother_original_owner
    return facility


def resolve_buyer(chip, transfer_logs):
    outs = [l for l in transfer_logs if l.chip == chip and l.type == '轉出']
    if not outs:
        return None
    latest_out = max(outs, key=lambda l: l.cert_serial)
    return {
        'date': latest_out.date,                  # = 售出日期
        'name': latest_out.counterparty_name,
        'id_no': latest_out.counterparty_id_no,
    }
```
